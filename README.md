# Classroom Press

A private class newspaper. Classmates open a GitHub Issue; a GitHub Action turns it
into a markdown article with a headline; Netlify builds the Astro site. Static output,
no server, no database, $0.

```
GitHub Issue (label: announcement)
   │
   ▼  GitHub Actions: ingest.yml  (Python 3.11, Layer 1)
   │   scripts/issue_to_article.py → headline (GitHub Models → validator → templates)
   │   generator/build.py          → web/public/data/{articles,sections,editions}.json
   │   commit content/, JSON, photos
   ▼
Netlify (Layer 2) sees the commit → `npm run build` in web/ → publishes web/dist
```

The model call lives **only** in Layer 1 at ingest time. Netlify never runs Python and never
calls a model; browser code never calls a model. Headlines are cached in front matter and are
never regenerated by the frontend build.

## The validator pattern

> The model only rewrites wording. The validator gates it. The template engine is the floor.

`generator/headline_gen.py` asks `openai/gpt-4o-mini` (GitHub Models, `GITHUB_TOKEN`) for a headline
using the fixed prompt, then rejects the output if it:

- is over 60 characters, multi-line or empty
- is not ALL CAPS
- contains any quote character (straight, curly, backtick; apostrophes count)
- drops a number from the **date or title**
- contains any number that is not in the input

Any rejection, API error, timeout or missing token falls back to `generator/headlines.py`, a seeded
template engine that works with zero model dependency and passes the same validator.
`generate_headline()` returns `(headline, "model" | "fallback")`; the Action logs which path ran.
If output ever looks wrong, fix the validator or the templates, not the prompt.

Subheads follow the same pattern (≤110 chars, sentence case, no invented numbers), with a
deterministic fallback built from the authored scope/requirement/location/restriction fields.

Numbers are compared as whole tokens. Scope numbers (e.g. `1-4`) are *allowed* in a headline but
not *required*, because the brief's own examples omit them.

## Submitting an article (for classmates)

1. Repo → **Issues → New issue → Announcement**.
2. Keep the `key: value` lines; fill in what you know. Use `YYYY-MM-DD` for `date`.
   Categories: `exam`, `deadline`, `event`, `academics`, `sports`, `general`.
3. Write the story under the fields. Submit.
4. Within a couple of minutes the bot commits `content/issue-<n>-<slug>.md` and Netlify republishes.

The issue needs the `announcement` label (the template adds it). Field values are copied verbatim;
only `headline` and `subhead` come from the model/templates. To fix text afterwards, edit the markdown
file in `content/`.

## Urgency and placement

Computed from the `date` (a date-only value is due at 23:59:59 that day in `CLASSROOM_TZ`):

| Time until due | Placement |
|---|---|
| < 24 h | breaking ticker + red headline |
| < 48 h | front-page banner |
| < 7 d | front page |
| > 7 d, past, or undated | archive only (pinned notices stay on the front page) |

Because this depends on the clock, `ingest.yml` also runs daily on a schedule to refresh the JSON
(and the edition number). Countdowns on the page update live in the browser.

## Netlify setup

1. Push this repo to GitHub. Enable **Settings → Actions → Workflow permissions: read and write**.
2. Netlify → **Add new site → Import from Git** → pick the repo. Settings are read from `netlify.toml`
   (base `web`, command `npm run build`, publish `dist`, Node 20). Do not add a deploy workflow.
3. Optionally rename the site so the URL matches `site` in `web/astro.config.mjs`.
4. `base` in `astro.config.mjs` must stay `'/'`. A repo subpath will 404 every asset on Netlify.
5. Run `npm install` once in `web/` and commit `package-lock.json`.
6. Create an `announcement` label in the repo.

Free tier (100 GB bandwidth, 300 build minutes per month) is far more than a class paper needs.
Note: the site is `noindex` and `robots.txt` disallows crawlers, but it is *unlisted*, not
password-protected. Netlify's site-password feature is a paid plan.

## Local development

```bash
pip install -r requirements.txt
python generator/build.py --no-increment      # rebuild JSON without bumping the edition
python generator/build.py --now 2026-10-12T09:00:00   # pin the clock for previews
pytest                                          # validator, templates, build, ingest
cd web && npm install && npm run dev
```

Try the ingest script locally (no token, so templates are used):

```bash
ISSUE_TITLE="Summative test" ISSUE_NUMBER=7 ISSUE_BODY=$'category: exam\nsubject: Math\ndate: 2026-10-20' \
  python scripts/issue_to_article.py
```

## Layout notes

- `content/*.md`: articles (YAML front matter + markdown). `issue_number` is the GitHub issue number.
- `static/photos/<category>/`: press photos (placeholders included; add your own). Chosen by `md5(slug)`;
  `default.svg` is the fallback. Optional `credits.json` per folder.
- `generator/state.json`: edition counter (+1 per build).
- Class name: `SITE.className` in `web/src/lib/loadArticles.ts`.
- JSON extras beyond the base schema: `due_at`, `scope`, `requirement`, `restriction` (per article).
